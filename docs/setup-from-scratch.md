# Setting up as1 and a Mac from scratch

One ordered checklist from a bare Ubuntu box and a bare Mac to the working setup: SSH or mosh from WezTerm
into tmux on as1, the three harnesses, and image paste into Claude Code. It says what to do, in what order,
on which machine, and how to know each step worked. The reasoning behind each choice is in
`remote-agent-host-plan.md`; the Mac steps in full detail, with rollback, are in `mac-client-setup.md`.

Conventions: `as1$` is a shell on as1, `mac$` a local shell on the Mac, `as1#` a root shell on as1.
Automated steps are marked **script**; everything else is manual. Every script is idempotent and safe to re-run.

## Parameters

The repo hardcodes one owner and one network. Rebuilding for the same owner needs no edits. For a
different user, host or LAN, change these in the same commit and re-run the install scripts.

| Value | Current | Where it lives |
|---|---|---|
| as1 login | `kyle` | `config/sshd/10-hardening.conf` (`AllowUsers`), `config/ssh_config.mac`, `config/wezterm-as1.lua`, `install-as1-root.sh` (default when not run via sudo) |
| as1 hostname (MagicDNS) | `as1`, `as1.manee-goby.ts.net` | `config/ssh_config.mac`, `config/wezterm-as1.lua`, both docs |
| as1 LAN address, LAN range | `192.168.10.2`, `192.168.10.0/24` | `config/ssh_config.mac` (`Host as1-lan`), `config/ufw.sh` |
| Macs | `macbook`, `mini` | docs only; nothing on as1 knows the Mac names |
| Repo | `github.com/kylenguyen/agentic-framework` | clone commands in the docs |
| Mac key | `~/.ssh/id_ed25519`, no passphrase | `config/ssh_config.mac`; generated by `install-mac.sh` if absent |

## Order of work

```
 A  as1 at the console      Ubuntu, user kyle with a password, sshd, Tailscale, git, clone repo
 B  Mac                     Homebrew, WezTerm, Tailscale app, clone repo, ./install-mac.sh (makes the key)
 C  Mac -> as1              put the Mac key on as1; `ssh as1 true` with no prompt
 D  as1 (sudo)              sudo bash install-as1-root.sh        sshd, ufw, apt, zsh, linger
 E  as1 (user)              ./install-as1.sh                     tmux, zsh, toolchains, harnesses, shim
 F  as1 (user)              one-time logins: claude, gh, secrets file
 G  Mac                     reload WezTerm, joint checkpoints
 H  second Mac              repeat B, C, G
```

A must finish before anything else. B and C need A. D needs C (keep a key-based session open while sshd reloads).
E needs D for zsh and tmux. G needs E. Total effort for one Mac and as1, without phases 5 and 6: about half a day.

## A. as1: bare metal to reachable

Done once at the console (keyboard and screen, or the hypervisor console). Nothing here comes from the repo.

1. Install Ubuntu Server LTS (the plan was written against 26.04). In the installer:
   - Hostname: `as1`. MagicDNS takes the OS hostname, and every `Host as1` in the repo relies on that name.
     (Fix later with `sudo tailscale up --hostname as1` if you missed it.)
   - User `kyle` with a real password. The root script in D refuses to run without one.
   - Tick "Install OpenSSH server".
   - "Import SSH identity" from GitHub: your choice, and it decides part C. Importing puts your GitHub
     keys in `authorized_keys` and makes the installer turn **off** password login over SSH
     (`/etc/ssh/sshd_config.d/50-cloud-init.conf`); a Mac whose key is on GitHub then logs in at once and
     skips C, but a Mac with a new key cannot use `ssh-copy-id` until D re-enables passwords. Not importing
     leaves password login on, so C is a plain `ssh-copy-id`. Either way D ends in the same state.
2. Give as1 a fixed LAN address. The repo assumes `192.168.10.2` on `192.168.10.0/24`; a DHCP reservation on
   the router is enough. Check with `ip -4 addr`. A different LAN means editing the two files in the
   parameters table before D, or accepting tailnet-only access.
3. Base packages and updates:
   ```
   as1$ sudo apt update && sudo apt full-upgrade -y && sudo apt install -y git curl
   ```
   Everything else is installed by the scripts in D and E.
4. Tailscale, and join the tailnet. `tailscale up` prints a login URL; open it on a device that is already
   signed in to the tailnet (the phone, or the Mac once B.3 is done):
   ```
   as1$ curl -fsSL https://tailscale.com/install.sh | sh
   as1$ sudo tailscale up
   as1$ tailscale status | head -1           # as1  100.x.y.z  ...
   as1$ tailscale dns status | grep -i magicdns   # enabled; if not, turn MagicDNS on in the admin console, DNS tab
   ```
   In the admin console, Machines, as1: "Disable key expiry", so a headless box never drops off the tailnet.
   Note the full name shown there (`as1.<tailnet>.ts.net`); if the tailnet differs from `manee-goby`, update the
   docs' verify commands that spell it out.
5. Confirm the password check that the root script will apply later:
   ```
   as1$ passwd -S kyle | awk '{print $2}'   # P. If NP or L: sudo passwd kyle
   ```
6. Clone the repo where the scripts expect it. No GitHub key exists on as1 yet, so use HTTPS. For a private
   repo, authenticate gh first; it also installs the git credential helper so the HTTPS clone works:
   ```
   as1$ sudo apt install -y gh && gh auth login      # only if the repo is private: GitHub.com, HTTPS, browser login, code on the Mac
   as1$ mkdir -p ~/workspace && git clone https://github.com/kylenguyen/agentic-framework.git ~/workspace/agentic-framework
   ```
7. Optional, only for phase 6: Docker (`sudo apt install -y docker.io && sudo usermod -aG docker kyle`).
   Not needed for anything in this document.

Verify A:
```
as1$ hostname; systemctl is-active ssh tailscaled   # as1, active, active
as1$ tailscale ip -4                                 # 100.x.y.z
as1$ sudo sshd -T | grep -i ^passwordauthentication  # yes or no: tells you which path C takes
as1$ ls ~/workspace/agentic-framework/install-as1.sh
```

## B. Mac: bare to installer run

1. FileVault on (System Settings, Privacy & Security). The installer in B.4 generates an SSH key with no
   passphrase, because the clipboard push runs it non-interactively; disk encryption is what protects it.
2. Homebrew: run the one-line installer from https://brew.sh in Terminal. It installs the Xcode command line
   tools first (a licence prompt and a few minutes). When it finishes it prints two lines to add Homebrew to
   PATH; run them, they append to `~/.zprofile`:
   ```
   mac$ echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile && eval "$(/opt/homebrew/bin/brew shellenv)"
   mac$ brew --version
   ```
   Without this, `install-mac.sh` stops at its first line with "Homebrew missing".
3. WezTerm: `brew install --cask wezterm`, or from the App Store or MDM catalogue on a managed Mac. Open it
   once so macOS registers it (approve the "downloaded from the internet" prompt if it appears).
4. Tailscale app: App Store or https://tailscale.com/download/mac. Sign in to the same tailnet. Menu bar icon,
   Preferences: tick "Start Tailscale on login"; leave "Use Tailscale DNS settings" on, that is what makes
   `as1` resolve; "Allow incoming connections" stays off.
5. Clone the repo and run the installer. The clone is HTTPS because a fresh Mac has no GitHub key. For a
   private repo, authenticate gh first (this is the `brew install gh` the Mac doc calls optional):
   ```
   mac$ brew install gh && gh auth login       # only if the repo is private: GitHub.com, HTTPS, browser login
   mac$ mkdir -p ~/workspace && git clone https://github.com/kylenguyen/agentic-framework.git ~/workspace/agentic-framework
   mac$ cd ~/workspace/agentic-framework && ./install-mac.sh
   ```
   **script**: it installs mosh and pngpaste, writes the `as1`, `as1-lan` and `as1-clip` blocks into
   `~/.ssh/config`, generates `~/.ssh/id_ed25519` if you have none, writes `~/.config/wezterm/wezterm.lua` if
   you have none (otherwise tells you the one line to add), installs `clip-push`, and adds a marker block to
   `~/.zshrc` that puts `~/.local/bin` on PATH. Its last lines test whether `ssh as1` logs in by key with no
   prompt and, if not, print the `ssh-copy-id` command for your situation. On a new Mac it will not; that is part C.
6. Open a new shell (or a WezTerm window) so the PATH change applies.

Verify B (Mac alone):
```
mac$ ssh -G as1 | grep -E '^(hostname|user|identityfile) '    # as1, kyle, ~/.ssh/id_ed25519
mac$ /Applications/Tailscale.app/Contents/MacOS/Tailscale status | grep as1   # listed, not offline
mac$ dns-sd -G v4 as1 | head -3                                  # resolves to 100.x.y.z (Ctrl+C)
mac$ grep -c wezterm-as1 ~/.config/wezterm/wezterm.lua           # 1
mac$ command -v clip-push && mosh --version | head -1            # ~/.local/bin/clip-push
```

## C. Put the Mac key on as1

Until the root script runs, sshd on as1 is whatever the installer left (see A.1 and the last line of Verify A).

The last lines of `install-mac.sh` diagnose this step and print the one command that fits; the cases are
spelled out here. The first connection is interactive on purpose: answer `yes` to the host-key prompt. That
entry in `~/.ssh/known_hosts` is what later lets `as1-clip` run in BatchMode, which never prompts and fails
silently without it. `Host as1` in `~/.ssh/config` supplies the user, so `as1` alone is the target.

**Fresh Mac, no key on as1 yet** (the normal case):
```
mac$ ssh-copy-id -i ~/.ssh/id_ed25519.pub as1      # host key: yes; then kyle's password, once
mac$ ssh as1 true && echo key-login-ok               # no prompt of any kind
```
The password prompt is expected here; it is the fallback the sshd config keeps for exactly this moment.

**Mac that already has a different key as1 trusts** (a key provisioned before this repo, under another name
such as `~/.ssh/id_rsa`). `ssh as1` then asks for a password, because `Host as1` offers only the repo key,
and `as1-clip` fails outright. Install the repo key over the trusted one, no password:
```
mac$ ssh-copy-id -f -i ~/.ssh/id_ed25519.pub -o IdentityFile=~/.ssh/id_rsa as1
```
`-f` is required. Without it ssh-copy-id first logs in with every explicit identity to skip keys it believes
are already installed; the `-o IdentityFile` makes that probe succeed with the old key, so it reports
"All keys were skipped because they already exist" and installs nothing.

**Repo key already trusted, only the host key missing**: `ssh as1`, answer `yes`, done.

If `ssh-copy-id` is refused with "Permission denied (publickey)", password login is off because a key was
imported in A.1. Then either:

- paste the Mac key at the console: `mac$ cat ~/.ssh/id_ed25519.pub`, and on as1
  `mkdir -p -m 700 ~/.ssh && echo '<that line>' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys`, or
- add the new Mac key to your GitHub account and run `ssh-import-id gh:<github-user>` on as1 at the console
  (the same mechanism the installer used).

After D the password path is on and bounded to the tailnet and LAN, so any later Mac can use `ssh-copy-id`.

`ssh as1 true` must succeed without a prompt before going on: mosh, the clipboard push and every
non-interactive `ssh as1 <command>` depend on the key path.

## D. as1 root steps

**script**. Keep the key-based session from C open in another tab while this runs: it reloads sshd.

```
mac$ ssh as1
as1$ cd ~/workspace/agentic-framework && sudo bash install-as1-root.sh
```

What it does, in order: refuses to continue unless `kyle` has a password; installs
`config/sshd/10-hardening.conf` (key or password for `kyle` only, no root, no empty passwords) and reloads
sshd; installs tmux, mosh, gh, zsh, git, curl, file, jq, unattended-upgrades; makes zsh the login shell;
applies `config/ufw.sh` (inbound only on `tailscale0`, plus SSH from the LAN); enables linger for `kyle`;
turns on Tailscale auto-update.

Verify D, from the open session and from a new one:
```
as1$ sudo sshd -T | grep -iE '^(passwordauthentication|permitrootlogin|allowusers) '   # yes, no, kyle
as1$ sudo ufw status verbose | grep -E 'Status|tailscale0|192.168.10'
as1$ loginctl show-user kyle | grep Linger                                             # Linger=yes
as1$ getent passwd kyle | cut -d: -f7                                                  # /usr/bin/zsh
mac$ ssh as1 true && echo still-ok                                                     # new connection through the new sshd
mac$ ssh -o PreferredAuthentications=password -o PubkeyAuthentication=no kyle@as1 true && echo password-ok
```

## E. as1 user steps

**script**. Run as `kyle`, no sudo. With network: clones oh-my-zsh, installs mise with Node, Bun and
Python 3.12, uv, OpenCode, Oh My Pi and Claude Code. `--no-tools` skips all downloads and only
renders configs.

```
as1$ cd ~/workspace/agentic-framework && ./install-as1.sh
```

It symlinks `~/.tmux.conf`, `~/.zshenv`, `~/.zshrc`, `~/.bashrc.d`, `~/.claude/settings.json`,
`~/.claude/statusline-command.sh`, `~/workspace/CLAUDE.md` and `~/workspace/AGENTS.md` into the repo,
adds two marker blocks to `~/.bashrc`, creates `~/.config/agents/env` from `env.example` (mode 600), and
installs the `xclip` shim and `clip-put` into `~/.local/bin`.

Then log out and back in. The new login lands in zsh with oh-my-zsh, inside tmux session `main`.
If a `main` session from before the root script is still running it keeps bash: `tmux kill-server`, log in again.

Verify E:
```
as1$ echo $ZSH_THEME $TMUX | cut -c1-40           # robbyrussell /tmp/tmux-...
as1$ for c in mise node bun python3.12 uv claude opencode omp; do printf '%-10s %s\n' $c "$(command -v $c || echo MISSING)"; done
as1$ command -v xclip                             # ~/.local/bin/xclip, not /usr/bin
as1$ stat -c '%a' ~/.config/agents/env            # 600
as1$ readlink ~/workspace/AGENTS.md               # .../config/workspace/CLAUDE.md
mac$ ssh as1 'echo tmux=$TMUX; command -v mise'   # tmux= (empty), then a mise path: non-interactive SSH gets PATH but no tmux
```

## F. One-time logins and secrets

Manual, and the only steps that hold credentials. Nothing here goes in the repo.

Both logins work on a headless box the same way: the CLI prints a URL and a one-time code, you open the URL
in the Mac's browser and enter the code, and the CLI on as1 completes on its own.

1. Claude Code. Either sign in once with OAuth (`as1$ claude`, pick the account type, open the printed URL on
   the Mac, paste the code back, then `/exit`) or put `ANTHROPIC_API_KEY` in the secrets file. OAuth is enough
   for interactive work; the API key is what `claude --bare` and the phase 5 automation use.
2. GitHub: `as1$ gh auth login`, GitHub.com, HTTPS, "Login with a web browser", enter the code at the URL it
   prints. If you did this in A.6 for a private clone, skip it. Leave the repo remote on HTTPS: the gh
   credential helper covers pushes, and no GitHub SSH key needs to live on as1. For agents, prefer a
   fine-grained token scoped to the repos they may touch, via `gh auth login --with-token`.
3. Secrets file: `as1$ $EDITOR ~/.config/agents/env`, uncomment and fill the keys you use. It is sourced
   by every shell, including `ssh as1 <cmd>`, and by the future systemd units. Claude Code is denied read
   access to it by `config/claude-settings.json`.
4. Optional, other harnesses: OpenCode reads `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` or
   `OPENROUTER_API_KEY` from the environment, so the same file covers it.

Verify F:
```
as1$ gh auth status
as1$ claude -p 'reply with the single word ok'                          # OAuth or key
as1$ zsh -c '[ -n "$ANTHROPIC_API_KEY" ] && echo secrets-in-noninteractive-zsh'
mac$ ssh as1 'claude --bare -p "reply with the single word ok"'         # key only; proves the env file reaches ssh commands
```

## G. Mac: finish and joint checkpoints

1. Reload WezTerm: Cmd+Shift+R. A config error shows as a red banner.
2. Run the joint checkpoints in `mac-client-setup.md`. The short version:

| Check | Expect |
|---|---|
| `mac$ mosh as1` | lands in tmux `main`; survives Wi-Fi off and on |
| Cmd+Shift+A | new WezTerm tab on as1 |
| tmux copy mode, select, Enter; `mac$ pbpaste` | the text |
| Cmd+Shift+Ctrl+4, then Cmd+V in `claude` on as1 | `[Image #1]` in the prompt |
| Cmd+V of text into a shell on as1 | pastes at once; `ls -l ~/.clip/latest` timestamp unchanged |
| `mac$ ssh as1 'echo $TMUX'` | empty line |

If the image paste fails: `mac$ clip-push` in a local terminal prints the ssh error the toast summarised;
`as1$ CLIP_BRIDGE_DEBUG=1 xclip -selection clipboard -t TARGETS -o` shows the shim's decision.

## H. Second Mac

Repeat B, C and G. Nothing on as1 is per-Mac; the clipboard spool holds whatever the last Mac pushed.
Part C on the second Mac can use the password path, which D has enabled.

## Rebuilding one side

- **as1 reinstalled, Macs unchanged**: A, then C (or the GitHub key import), D, E, F. On each Mac,
  remove the stale host key (`mac$ ssh-keygen -R as1; ssh-keygen -R 192.168.10.2`) before C.
- **Mac reinstalled, as1 unchanged**: B, C, G. `ssh-copy-id` works over the password path.
- **Mac that reached as1 before this repo**, with its own key: B, then the `-f` form in C, then G.
- **Config change in the repo**: `git pull` on each machine and re-run `./install-as1.sh --no-tools`
  or `./install-mac.sh`. Symlinked configs pick up the change without a re-run.

## What is not scripted

Kept manual on purpose, so a re-run can never lock you out or leak a credential:

- Ubuntu install, LAN address, Tailscale join and key-expiry setting (A).
- FileVault, Homebrew, WezTerm and Tailscale app on the Mac (B). `install-mac.sh` only tells you when they are missing.
- Copying the Mac key to as1 and accepting its host key (C).
- OAuth and token logins, and the contents of `~/.config/agents/env` (F).
- Docker for phase 6, and everything in phases 5 and 6 of the plan, which are designed but not built.
  `AGENTS.md` carries the current status table.
