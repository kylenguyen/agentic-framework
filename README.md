# agentic-framework

Source of truth for one headless Ubuntu box on a Tailscale tailnet that runs coding agents (Claude Code,
OpenCode, Oh My Pi), and for any number of Macs that reach it from WezTerm over SSH or mosh. Nothing in the repo
names a particular machine: the host's ssh alias, address, login and LAN range are parameters (`.env`, table below).
In the examples `<host>` stands for the alias (`AGENT_HOST`), `<user>` for the login (`AGENT_HOST_USER`), `<lan-ip>`
and `<lan-cidr>` for the LAN values. Two idempotent scripts do all the configuration; configs on the host are
symlinks into this checkout, so edit here, never the installed copy.

| Script | Runs on | As | Does |
|---|---|---|---|
| `install-host.sh` | host | the host login; `sudo` per command, only for phase 1 steps not yet done | phase 1: sshd hardening, apt packages, zsh as login shell, ufw, linger, Tailscale auto-update; then symlinked configs, secrets file skeleton, `xclip` shim, oh-my-zsh, mise toolchains, uv, the three harnesses |
| `install-mac.sh` | Mac | you, no sudo | mosh, pngpaste, `~/.ssh/config` block, SSH key and key login to the host, WezTerm include, `clip-push` |

Order: host prerequisites, then the Mac script (it puts the Mac key on the host), then the host script, then
one-time logins, then the joint checkpoints. Keep a key-based SSH session open while the host script runs;
its phase 1 reloads sshd.

Conventions: `host$` is a shell on the host, `mac$` a local shell on any of the Macs.

### Parameters

No script, template or config carries a host name, address or login. They come from `.env` at the repo root
(gitignored; template `.env.example`; rules in `lib/params.sh`), or from the system on the host:

| Parameter | Meaning | Host (`install-host.sh`) | Mac (`install-mac.sh`) |
|---|---|---|---|
| `AGENT_HOST` | ssh alias and WezTerm domain name | `hostname -s` | `.env`, required |
| `AGENT_HOST_ADDRESS` | what the Mac connects to | Tailscale MagicDNS name, else `AGENT_HOST` | `.env`, default `AGENT_HOST` |
| `AGENT_HOST_USER` | login on the host: sshd `AllowUsers`, ssh `User` | the login running the script; `.env` must agree | `.env`, required |
| `AGENT_HOST_LAN_IP` | host address on the LAN, for `ssh <alias>-lan` | `src` of the default route | `.env`, optional |
| `AGENT_HOST_LAN_CIDR` | LAN range ufw lets ssh in from | connected route of the default interface; must be RFC 1918 unless set in `.env` | not used |

`.env` values override the derived ones, except the login. The host script writes `.env` on its first run and
prints the lines for the Macs at the end. On a Mac, copy `.env.example` to `.env` and edit it, or let the script
ask. Files that need a parameter are `.in` templates rendered at install time: `config/sshd/10-hardening.conf.in`,
`config/ssh_config.mac.in`, `config/wezterm-agent-host.lua.in`, `bin/clip-push-mac.sh.in`. Not parameters: the Macs
themselves (nothing on the host knows which Mac is connected, and every Mac uses the same `.env`), the repo URL in the
clone commands, the Mac key `~/.ssh/id_ed25519` (no passphrase, generated by `install-mac.sh` if absent), `~/workspace`,
tmux session `main`.

## 1. Host prerequisites (console, once)

Manual on purpose, so a script re-run can never lock you out.

1. Install Ubuntu Server LTS. Pick a short hostname (it becomes `<host>`, the ssh alias on every Mac) and a login
   (`<user>`) with a real password, tick "Install OpenSSH server". The login becomes the only account sshd allows.
   Importing a GitHub SSH identity is optional; it turns password login off until the host script runs,
   so a Mac with a new key must then have its key pasted at the console instead of `ssh-copy-id`.
2. Fixed LAN address `<lan-ip>` (DHCP reservation on the router), so `ssh <host>-lan` keeps working off the tailnet.
3. Base packages, Tailscale, repo clone:
   ```
   host$ sudo apt update && sudo apt full-upgrade -y && sudo apt install -y git curl
   host$ curl -fsSL https://tailscale.com/install.sh | sh && sudo tailscale up     # open the URL on a signed-in device
   host$ mkdir -p ~/workspace && git clone https://github.com/kylenguyen/agentic-framework.git ~/workspace/agentic-framework
   ```
   In the Tailscale admin console: MagicDNS on, and "Disable key expiry" for <host>. For a private repo,
   `sudo apt install -y gh && gh auth login` before the clone.

Verify:
```
host$ hostname; systemctl is-active ssh tailscaled           # the hostname you picked, active, active
host$ tailscale ip -4                                         # 100.x.y.z
host$ passwd -S <user> | awk '{print $2}'                       # P (a password is set)
host$ sudo sshd -T | grep -i ^passwordauthentication          # yes, unless a GitHub key was imported
host$ ls ~/workspace/agentic-framework/install-host.sh
```

## 2. Mac client

Prerequisites, manual: FileVault on (the SSH key has no passphrase), Homebrew, WezTerm
(`brew install --cask wezterm`), and the Tailscale app signed in to the same tailnet with
"Start Tailscale on login" ticked and Tailscale DNS on.

```
mac$ mkdir -p ~/workspace && git clone https://github.com/kylenguyen/agentic-framework.git ~/workspace/agentic-framework
mac$ cd ~/workspace/agentic-framework && cp .env.example .env && $EDITOR .env
mac$ ./install-mac.sh
```

`.env` on the Mac: `AGENT_HOST` is the hostname chosen in section 1 (it becomes `ssh <alias>` and the WezTerm domain),
`AGENT_HOST_ADDRESS` the same name once MagicDNS is on (or the Tailscale IP from `tailscale ip -4`), `AGENT_HOST_USER`
the login from section 1, `AGENT_HOST_LAN_IP` the reserved LAN address; `AGENT_HOST_LAN_CIDR` is ignored on a Mac. Once
the host script has run it prints exactly these lines, so a second Mac can copy them.

Run it in a terminal, not from a pipe. It prints the parameters it read (with no `.env` it asks for them and
writes the file), installs mosh and pngpaste, writes the `<host>`, `<host>-lan` and `<host>-clip` blocks into
`~/.ssh/config` (the `agentic-framework:agent-host` marker block; no `<host>-lan` without a LAN address), generates
`~/.ssh/id_ed25519` if absent, renders and installs the WezTerm include (writes a minimal `wezterm.lua` if you have
none, otherwise adds the one `require("wezterm-agent-host")` line before your `return config`, keeping the original
as `wezterm.lua.before-agent-host`; the include also sets the shared colour scheme, Tokyo Night, unless your `wezterm.lua`
sets `config.color_scheme` itself), installs `clip-push`, puts `~/.local/bin` on PATH via `~/.zshrc`, and finally
makes `ssh <host>` log in by key with no prompt. On first contact it stores the host key; if the host trusts no local
key it runs `ssh-copy-id` and asks for the host password once. It ends with `ok   ssh <host> logs in by key`.

It exits 1, with the command to run, when: <host> is unreachable (check Tailscale); a stored host key no longer
matches after a reinstall (`ssh-keygen -R <host>; ssh-keygen -R <lan-ip>`); or password login is off and no
key is trusted (paste `~/.ssh/id_ed25519.pub` into `~/.ssh/authorized_keys` on <host> at the console). Fix and re-run.

Then open a new shell and reload WezTerm with Cmd+Shift+R.

Verify (Mac alone):
```
mac$ ssh -G <host> | grep -E '^(hostname|user|identityfile) '                  # <host>, <user>, ~/.ssh/id_ed25519
mac$ ssh -G <host>-clip | grep -E '^(batchmode|controlmaster|connecttimeout) ' # yes, auto, 3
mac$ /Applications/Tailscale.app/Contents/MacOS/Tailscale status | grep <host> # listed, not offline
mac$ grep -c wezterm-agent-host ~/.config/wezterm/wezterm.lua               # 1
mac$ command -v clip-push && mosh --version | head -1                       # ~/.local/bin/clip-push
mac$ ssh <host> true && echo key-login-ok                                      # no prompt
```

## 3. Host script

```
mac$ ssh <host>
host$ cd ~/workspace/agentic-framework && ./install-host.sh        # --no-tools skips network installs, --no-root skips phase 1
```

Run it as the host login (`<user>`), never with `sudo`. It starts by printing the parameters it derived (host name,
Tailscale name, login, LAN address and range) and writes `.env` if there is none; edit `.env` and re-run to
override. Phase 1 runs the root steps one command at a time through `sudo`, each only when the host is not already
in the wanted state, so `sudo` asks for your password once on a fresh host and not at all on a re-run of a
configured one. It refuses to start phase 1 unless the login has a password. It renders
`config/sshd/10-hardening.conf.in` for that login (key or password for that login only, no root, no empty
passwords), installs it when the directives differ from what is installed, and reloads sshd; installs tmux, mosh,
gh, zsh, git, curl, file, jq, unattended-upgrades; sets zsh as the login shell; applies `config/ufw.sh` with the LAN
range (inbound only on `tailscale0`, plus SSH from the LAN; a derived range must be private); enables linger; turns
on Tailscale auto-update and unattended-upgrades.

Phases 2 to 4 run as the login: symlink `~/.tmux.conf`, `~/.zshenv`, `~/.zshrc`, `~/.bashrc.d`, `~/.claude/settings.json`,
`~/.claude/statusline-command.sh`, `~/workspace/CLAUDE.md` and `~/workspace/AGENTS.md` into the repo; create
`~/.config/agents/env` from `secrets.env.example` (mode 600); install the `xclip` shim and `clip-put`; with network,
install oh-my-zsh, mise with Node, Bun and Python 3.12, uv, OpenCode, Oh My Pi and Claude Code. It ends by printing
the `.env` lines for the Macs.

Log out and back in. The new login lands in zsh inside tmux session `main`. If an older `main` session still
runs bash: `tmux kill-server`, log in again.

Verify, from the open session and a new one:
```
host$ sudo sshd -T | grep -iE '^(passwordauthentication|permitrootlogin|allowusers) '   # yes, no, <user>
host$ sudo ufw status verbose | grep -E 'Status|tailscale0|22/tcp'    # active; tailscale0 allowed; 22 from <lan-cidr>
host$ loginctl show-user <user> | grep Linger                                             # Linger=yes
host$ getent passwd <user> | cut -d: -f7                                                  # /usr/bin/zsh
mac$ ssh <host> true && echo still-ok
mac$ ssh -o PreferredAuthentications=password -o PubkeyAuthentication=no <user>@<host> true && echo password-ok
host$ echo $ZSH_THEME $TMUX | cut -c1-40           # robbyrussell /tmp/tmux-...
host$ for c in mise node bun python3.12 uv claude opencode omp; do printf '%-10s %s\n' $c "$(command -v $c || echo MISSING)"; done
host$ command -v xclip                             # ~/.local/bin/xclip, not /usr/bin
host$ stat -c '%a' ~/.config/agents/env            # 600
host$ readlink ~/workspace/AGENTS.md               # .../config/workspace/CLAUDE.md
host$ cat ~/workspace/agentic-framework/.env       # the five AGENT_HOST_* lines, same values install-host.sh printed
host$ bash ~/workspace/agentic-framework/tests/params-test.sh | tail -1   # N passed, 0 failed
mac$ ssh <host> 'echo tmux=$TMUX; command -v mise'   # tmux= (empty), then a mise path
```

## 4. One-time logins and secrets (host, manual)

Both logins print a URL and a code; open the URL in the Mac's browser.

1. Claude Code: `host$ claude`, sign in, `/exit`. Or put `ANTHROPIC_API_KEY` in the secrets file; that is what
   `claude --bare` and non-interactive use need.
2. GitHub: `host$ gh auth login` (GitHub.com, HTTPS, browser). Keep the repo remote on HTTPS.
3. Secrets: `host$ $EDITOR ~/.config/agents/env`. Sourced by every shell, including `ssh <host> <cmd>`. Claude Code
   is denied read access to it by `config/claude-settings.json`.

Verify:
```
host$ gh auth status
host$ claude -p 'reply with the single word ok'
mac$ ssh <host> 'claude --bare -p "reply with the single word ok"'    # needs the API key; proves the env file reaches ssh commands
```

## 5. Joint checkpoints (a Mac and the host together)

| Check | Expect |
|---|---|
| `mac$ mosh <host>` | lands in tmux `main`; survives Wi-Fi off and on |
| Cmd+Shift+A in WezTerm | new tab on <host> |
| tmux copy mode (Ctrl+B `[`, Space, Enter), then `mac$ pbpaste` | the copied text |
| Cmd+Shift+Ctrl+4, then Cmd+V in `claude` on <host> | `[Image #1]` in the prompt |
| Cmd+V of text into a shell on <host> | pastes at once; `ls -l ~/.clip/latest` timestamp unchanged |
| `mac$ ssh <host> 'echo $TMUX'` | empty line |

Clipboard bridge checks from the Mac (take a screenshot first):
```
mac$ clip-push && ssh <host> 'file ~/.clip/latest'     # image/png, then PNG image data
mac$ time clip-push                                 # well under 1 s on the second run
mac$ clip-push --clear && ssh <host> 'ls ~/.clip'      # nothing listed
```

If image paste fails: `mac$ clip-push` in a local terminal prints the ssh error;
`host$ CLIP_BRIDGE_DEBUG=1 xclip -selection clipboard -t TARGETS -o` shows the shim's decision.

## More Macs and rebuilds

- Every further Mac: section 2 only, with the same `.env` (the host script prints it), then the checkpoints. Nothing
  on the host is per-Mac; the clipboard spool holds whatever the last Mac pushed.
- Host reinstalled: section 1, then on each Mac `ssh-keygen -R <host>; ssh-keygen -R <lan-ip>` (the address and
  LAN address from `.env`; the script prints the exact command) and re-run `./install-mac.sh`, then sections 3 and 4.
- Different host name, login or LAN: nothing to edit in the repo. On the host, `hostname`, the login and the
  network decide; on the Mac, `.env` does.
- Config change in the repo: `git pull` and re-run `./install-host.sh --no-tools` or `./install-mac.sh`. Phase 1
  skips every step that is already in place and asks for `sudo` only if, say, `config/sshd` changed.
  Symlinked configs pick up the change without a re-run. Run the host script from `~/workspace/agentic-framework`,
  never from a worktree: the symlinks follow the checkout it runs from.

## Rollback (Mac)

- Clipboard push: `rm ~/.local/bin/clip-push`, delete the `Host <host>-clip` block from `~/.ssh/config` (inside the
  `agentic-framework:agent-host` markers), reload WezTerm. On the host: `rm ~/.local/bin/clip-put ~/.local/bin/xclip && rm -rf ~/.clip`.
- WezTerm include: delete the `require("wezterm-agent-host")` line from `wezterm.lua`, or restore `wezterm.lua.before-agent-host`
  if the script edited it; `rm ~/.config/wezterm/wezterm-agent-host.lua`.
- ssh config: delete the block between the `agentic-framework:agent-host` markers; PATH: the `agentic-framework:path` block in `~/.zshrc`.
